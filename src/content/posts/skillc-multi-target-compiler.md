skillc 是我写的多运行时 Skill 编译器。起因很朴素：我写了一份 Skill，在 Claude Code 里能用，换到 Codex 就失灵。

问题不在内容，而在**契约**——每个运行时对 Skill 的存放位置、文件命名、元数据格式、是否支持子目录，都有自己的一套约定。

所以 skillc 的思路是：把 Skill 当作源码，把各运行时的要求当作目标平台，**编译**出不同的产物，而不是靠人工维护 N 份副本。

怎么证明它真的在"编译"而不是"复制"？我让 skillc 对每个目标输出产物哈希：

```
claude-code → c5723df45b835fce
codex       → 34698be136514253
```

两份产物哈希不同，说明确实按目标做了转换。如果只是把同一份文件复制到不同目录，哈希会完全一致——那不叫编译器，那叫 `cp`。

这个哈希差异后来成了我最常引用的证据。因为"我适配了多个运行时"是一句可以随口说的话，而"两个目标的产物哈希不同"是一条可以被别人复跑验证的记录。

我的体会是：**给工具加一个能自证的输出，比在 README 里写十行介绍有用。** 前者是证据，后者只是声明。
